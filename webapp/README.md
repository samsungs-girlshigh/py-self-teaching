# 코드 대륙 모험기 — 1~4단계

고등학교 정보 교과서 3단원(변수~표준입출력) 4개 스테이지가 제작된 버전입니다. 전체 커리큘럼과 설계 원칙은 `코드대륙_모험기_시나리오_커리큘럼매핑.md`를 참고하세요.

## 진행 현황

| # | 단원 | 개념 | 스테이지 | 상태 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | 3단원 | 변수 | 시작의 마을 - 캐릭터 각성 | ✅ 완료 |
| 2 | 3단원 | 자료형 | 시작의 마을 - 스탯 창 | ✅ 완료 |
| 3 | 3단원 | 연산자 | 연산의 관문 | ✅ 완료 |
| 4 | 3단원 | 표준입출력 | 대화의 숲 | ✅ 완료 |
| 5 | 3단원 | 파일입출력 | 기억의 동굴 | 예정 |
| 6~19 | 3~6단원 | (리스트~객체지향 등) | - | 예정 |

## 4단계(표준입출력) 관련 기술 메모

- `input()`을 실제로 지원하도록 `pyodide-worker.js`를 수정했습니다. 각 문제 JSON에 `inputValues` 배열(문자열 목록)을 넣으면, 코드 안의 `input()` 호출이 호출된 순서대로 그 값을 돌려받습니다. (예: `"inputValues": ["16"]`)
- `input()`의 반환값은 항상 문자열이므로, 숫자 계산이 필요한 문제는 `int()`/`float()` 변환 여부를 오답 포인트로 활용했습니다.
- 입력값 목록보다 `input()` 호출 횟수가 많으면 빈 문자열(`""`)을 반환합니다(에러 대신 안전하게 처리).

## 폴더 구조

```
webapp/
  index.html          - 개발/테스트용 임시 진입 페이지
  stage.html           - 모든 스테이지가 공유하는 화면 템플릿 (?id=스테이지ID 로 어떤 스테이지인지 결정)
  hub.html             - 전체 스테이지 링크 허브 (기본 교사 전용, PIN으로 열람 + 공개 토글)
  dashboard.html        - 교사용 학습 현황 대시보드
  assets/
    css/style.css
    js/
      config.js          - 앱스 스크립트 URL, 스테이지 목록 설정  ← 배포 전 반드시 수정
      identify.js         - 학년/반/번호/이름 식별 화면
      pyodide-worker.js    - Web Worker 안에서 파이썬 코드 실행
      pyodide-client.js    - 워커 호출 + 타임아웃(무한루프 방지) 처리
      api.js              - 앱스 스크립트 백엔드 호출
      stage-engine.js      - 스테이지 렌더링 및 채점 흐름
      hub.js / dashboard.js
  data/stages/
    stage1_variables.json
    stage2_datatypes.json
    stage3_operators.json
  appsscript/
    Code.gs             - 구글 앱스 스크립트 백엔드 코드
    README.md           - 백엔드 설치 방법 (필독)
```

## 실행 순서 (처음 테스트할 때)

1. **백엔드 먼저 설정**: `appsscript/README.md` 를 따라 구글 시트 + 앱스 스크립트를 배포하고 웹앱 URL을 받습니다.
2. `assets/js/config.js` 의 `APPS_SCRIPT_URL` 을 그 URL로 바꿉니다.
3. `webapp` 폴더 전체를 정적 웹 호스팅(GitHub Pages, Netlify, 학교 웹호스팅 등)에 업로드합니다.
   - 로컬에서 먼저 확인하고 싶다면, `webapp` 폴더에서 `python3 -m http.server 8000` 실행 후 `http://localhost:8000` 접속 (Pyodide는 인터넷 연결이 필요합니다)
4. `index.html` 로 접속해 1단계부터 순서대로 진행해 봅니다.
5. `hub.html` 에서 Apps Script에서 설정한 PIN으로 로그인해 공개 토글, 대시보드가 잘 동작하는지 확인합니다.

## 확인해볼 체크리스트

- [ ] 처음 스테이지 접속 시 학년/반/번호/이름 입력 화면이 뜨는가
- [ ] 같은 브라우저에서 다음 스테이지로 넘어가면 입력했던 정보가 자동으로 채워지는가
- [ ] 보기를 선택하고 "선택한 보기 실행해보기"를 누르면 실제 실행 결과가 뜨는가
- [ ] 무한 루프에 가까운 코드를 실행시켜도 화면이 멈추지 않고 일정 시간 후 오류 메시지가 뜨는가 (타임아웃 확인용, 필요하면 임시로 `while True: pass` 같은 옵션을 넣어 테스트)
- [ ] "이 답으로 제출하기"를 누르면 정답/오답 판정이 오고, 구글 시트에 기록이 쌓이는가
- [ ] 같은 학생 정보로 같은 문제를 여러 번 제출하면 새 행이 생기지 않고 제출횟수만 올라가는가
- [ ] 모든 문제를 맞히면 다음 스테이지 링크가 나타나는가
- [ ] 허브 페이지가 기본적으로 비공개이고, PIN 입력 후에만 관리자 화면이 보이는가
- [ ] 공개 토글을 켜면 (다른 브라우저/시크릿창에서) 허브 페이지가 링크 목록을 그냥 보여주는가
- [ ] 대시보드에서 학생별 정답율, 반별(전체 학생 중 정답 도달 비율), 제출횟수, 최종제출시각이 표시되는가

## 다음 단계

같은 패턴(`data/stages/*.json` 추가 + `assets/js/config.js`의 `STAGE_LIST`에 등록 + `appsscript/Code.gs`의 `ANSWER_KEY`에 정답 추가)으로 5단계(파일입출력, "기억의 동굴")부터 이어서 제작합니다. 커리큘럼 전체 순서는 매핑 문서의 2절 표를 따릅니다.
