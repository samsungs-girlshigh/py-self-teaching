# 코드 대륙 모험기 — 1~4단계

고등학교 정보 교과서 3단원(변수~표준입출력) 4개 스테이지가 제작된 버전입니다. 전체 커리큘럼과 설계 원칙은 `코드대륙_모험기_시나리오_커리큘럼매핑.md`를 참고하세요.

## 15단계(탐색 알고리즘) 관련 메모

- 순차 탐색: 인덱스가 아닌 True/False나 값 자체를 반환하는 실수, 찾은 뒤에도 멈추지 않고 계속 순회해 마지막 매칭 위치를 반환하는 실수(중복 아이템이 있는 데이터로 검증)를 오답으로 반영했습니다.
- 이진 탐색: 범위를 좁힐 때 `+1`/`-1`을 빠뜨려 무한 루프가 되는 경우(실제 타임아웃까지 확인), 비교 부등호 방향이 반대인 경우, `while` 조건에서 등호를 빠뜨려 경계값을 놓치는 경우를 오답으로 반영했습니다.

## 16단계(모듈/라이브러리) 관련 메모

- `import` 자체를 빠뜨리거나 엉뚱한 모듈을 불러와 필요한 이름이 정의되지 않는 실수(`NameError`), 모듈 이름 오타(`ModuleNotFoundError`), 함수 이름 오타(`AttributeError`)를 오답으로 반영했습니다.
- `math.ceil`(올림)과 `math.floor`(내림)처럼 비슷해 보이지만 결과가 다른 함수를 혼동하는 경우도 오답으로 반영했습니다.
- `random` 문제는 결과값 자체가 매번 달라지므로, 커리큘럼 문서의 원칙대로 "선택한 코드가 올바른가"(정수 타입인지, 에러가 안 나는지)로 검증하도록 설계했습니다.

## 14단계(지역/전역 변수) 관련 메모

- `global` 선언 없이 함수 안에서 전역 변수와 같은 이름에 값을 대입하려는 흔한 실수(`UnboundLocalError`), `global` 선언을 대입 뒤에 적어 문법 에러가 나는 경우를 오답으로 반영했습니다.
- 매개변수로 값을 받아 지역적으로 계산 후 `return`하는 "더 안전한 패턴"도 함께 다루며, 반환값을 다시 대입하지 않는 실수, 인자를 빠뜨려 `TypeError`가 나는 실수를 오답으로 반영했습니다.

## 13단계(함수) 관련 메모

- `return` 대신 함수 안에서 `print`만 해서 실제 반환값이 `None`이 되는 실수, 매개변수 순서를 계산식 안에서 뒤바꾸는 실수, `def` 뒤 콜론을 빠뜨리는 문법 실수를 오답으로 반영했습니다.
- 함수 호출 결과를 변수에 다시 대입하지 않아 값이 갱신 안 되는 실수, 인자 전달 순서를 반대로 넣는 실수(뺄셈처럼 순서가 중요한 연산이라 결과가 확실히 달라짐), 함수 이름 오타(`NameError`)를 오답으로 반영했습니다.

## 12단계(정렬 알고리즘) 관련 메모

- 버블 정렬: 비교 부등호를 반대로 써서 내림차순이 되는 실수, 임시 변수 없이 두 줄로 교환해서 값이 손실되는 흔한 실수(`a = b; b = a`), 안쪽 반복 범위를 잘못 잡아 `IndexError`가 나는 경우를 오답으로 반영했습니다.
- 선택 정렬: 최솟값 인덱스를 매번 0으로 리셋해 이미 정렬된 부분을 다시 건드리는 실수, 최댓값을 찾아 내림차순이 되는 실수, 교환(swap)을 안쪽 반복문 안에 잘못 넣어 매번 뒤바뀌는 실수를 오답으로 반영했습니다.
- 커리큘럼 문서에 언급된 "교환 횟수 시각화"는 이번 파일럿에서는 생략하고, 이후 확장 과제로 남겨두었습니다.

## 11단계(break/continue) 관련 메모

- `break`와 `continue`를 서로 바꿔 쓰는 실수(반복을 완전히 끝내야 하는데 건너뛰기만 하거나, 반대로), 조건을 잘못 짚어 엉뚱한 시점에 반응하는 실수, 들여쓰기를 잘못해 `break`/`continue`가 반복문 흐름과 다르게 동작하는 경우(문법 에러가 나거나 매번 실행되는 경우)를 오답으로 반영했습니다.

## 10단계(반복문) 관련 메모

- `range()`의 시작/끝 인덱스 규칙(끝 값은 포함 안 됨)을 헷갈리는 off-by-one 실수, 범위를 짧게 잡는 실수, 시작·끝을 반대로 써서 아예 실행이 안 되는 경우를 오답으로 반영했습니다.
- while 문제는 실제로 **무한 루프가 되는 오답 2개**(증감문이 들여쓰기 밖에 있는 경우, 증감 방향이 반대인 경우)를 포함시켰습니다. 학생이 이 보기를 "실행해보기"로 눌러보면 4초 뒤 시간 초과 메시지가 뜨는 것까지 학습 경험으로 의도했습니다.

## 9단계(다중 조건문) 관련 메모

- elif 대신 독립된 if를 여러 개 쓰면 마지막 참인 조건이 앞의 결과를 덮어써버리는 실수, elif 조건 순서를 뒤바꿔 좁은 범위가 먼저 걸려버리는 실수, 부등호 경계(`>=`/`>`)를 오답으로 반영했습니다.
- 문자열 비교 문제에서는 elif 없이 조건이 거짓일 때 값이 `None`으로 남는 실수, 조건 문자열 오타(예: 공백 하나 차이), `=`/`==` 혼동을 오답으로 반영했습니다.

## 8단계(조건문) 관련 메모

- if/else의 조건 방향을 반대로 쓰는 실수, else 없이 if만 반복해 조건이 거짓일 때 아무 결과도 안 나오는 실수, `=`/`==` 혼동을 오답으로 반영했습니다.
- 중첩 if 문제는 "열쇠는 없지만 체력은 있는" 케이스로 설계해, `and`처럼 두 조건을 모두 확인해야 하는 상황에서 조건 하나를 빠뜨리거나 들여쓰기를 잘못하면 결과가 달라지는 것을 보여줍니다.

## 7단계(2차원 리스트) 관련 메모

- `dungeon_map[행][열]` 인덱싱과, 행/열 순서를 바꿔 짚는 흔한 실수(`[2][0]` vs `[0][2]`)를 값이 서로 다르게 나오도록 지도를 비대칭으로 설계했습니다.
- 이중 반복문에서 `count = 0` 초기화 위치를 반복문 안에 잘못 넣는 실수, `=`/`==` 혼동(문법 에러 — 파이썬이 `Maybe you meant '=='` 힌트까지 보여줌)을 오답으로 반영했습니다.

## 6단계(1차원 리스트) 관련 메모

- append/remove/sort의 흔한 실수를 오답으로 반영했습니다: 문자열을 `+=`로 리스트에 더하면 한 글자씩 쪼개져 들어가는 점, `insert`로 엉뚱한 위치에 넣는 점, `remove`에 없는 값을 넣으면 `ValueError`가 나는 점, `sort()`는 반환값이 없어(`None`) 대입하면 안 되는 점 등을 실제 실행 결과로 확인할 수 있습니다.

## 5단계(파일입출력) 관련 메모

- 실제 컴퓨터 파일(`open()`)을 열고 닫는 대신, 문자열 변수(`save_data`)로 "가상 세이브 파일"을 흉내 냈습니다. 개념 카드에 실제 `open("save.txt", "a")` 형태도 함께 언급해 실제 파일 처리와의 연결고리를 남겼습니다.
- 이어쓰기(`+=`)와 덮어쓰기(`=`)의 차이, `split()`으로 구분자 기준 데이터를 나눌 때 인덱스를 잘못 짚는 실수를 오답 포인트로 활용했습니다.

## 4단계(표준입출력) 관련 기술 메모

- `input()`을 실제로 지원하도록 `pyodide-worker.js`를 수정했습니다. 각 문제 JSON에 `inputValues` 배열(문자열 목록)을 넣으면, 코드 안의 `input()` 호출이 호출된 순서대로 그 값을 돌려받습니다. (예: `"inputValues": ["16"]`)
- `input()`의 반환값은 항상 문자열이므로, 숫자 계산이 필요한 문제는 `int()`/`float()` 변환 여부를 오답 포인트로 활용했습니다.
- 입력값 목록보다 `input()` 호출 횟수가 많으면 빈 문자열(`""`)을 반환합니다(에러 대신 안전하게 처리).

## 실행 순서 (처음 테스트할 때)

1. **백엔드 먼저 설정**: `appsscript/README.md` 를 따라 구글 시트 + 앱스 스크립트를 배포하고 웹앱 URL을 받습니다.
2. `assets/js/config.js` 의 `APPS_SCRIPT_URL` 을 그 URL로 바꿉니다.
3. 이 저장소 전체를 정적 웹 호스팅(GitHub Pages, Netlify, 학교 웹호스팅 등)에 업로드합니다. (저장소 루트가 곧 웹 루트이므로 별도 하위 폴더 지정 없이 바로 배포 가능합니다.)
   - 로컬에서 먼저 확인하고 싶다면, 저장소 루트에서 `python3 -m http.server 8000` 실행 후 `http://localhost:8000` 접속 (Pyodide는 인터넷 연결이 필요합니다)
4. `index.html` 로 접속해 1단계부터 순서대로 진행해 봅니다.
5. `hub.html` 에서 Apps Script에서 설정한 PIN으로 로그인해 공개 토글, 대시보드가 잘 동작하는지 확인합니다.

## 확인해볼 체크리스트

- [ ] 처음 스테이지 접속 시 학년/반/번호/이름 입력 화면이 뜨는가
- [ ] 같은 브라우저에서 다음 스테이지로 넘어가면 입력했던 정보가 자동으로 채워지는가
- [ ] 보기를 선택하고 "선택한 보기 실행해보기"를 누르면 실제 실행 결과가 뜨는가
- [ ] 무한 루프에 가까운 코드를 실행시켜도 화면이 멈추지 않고 일정 시간 후 오류 메시지가 뜨는가 (타임아웃 확인용, 필요하면 임시로 `while True: pass` 같은 옵션을 넣어 테스트)
- [ ] "이 답으로 제출하기"를 누르면 정답/오답 판정이 오고, 구글 시트에 기록이 쌓이는가
- [ ] 같은 학생 정보로 같은 문제를 여러 번 제출하면 새 행이 생기지 않고 제출횟수만 올라가는가
- [ ] 모든 문제를 맞히면 다음 스테이지 링크가 나타나는가
- [ ] 허브 페이지가 기본적으로 비공개이고, PIN 입력 후에만 관리자 화면이 보이는가
- [ ] 공개 토글을 켜면 (다른 브라우저/시크릿창에서) 허브 페이지가 링크 목록을 그냥 보여주는가
- [ ] 대시보드에서 학생별 정답율, 반별(전체 학생 중 정답 도달 비율), 제출횟수, 최종제출시각이 표시되는가

## 알려진 이슈 수정 이력

- **정답 위치 편중 수정**: 1~13단계 전체에서 각 문항의 보기 순서가 만들 때 항상 "정답을 1번째 옵션으로 작성"한 습관 때문에 실제 화면에서도 정답이 항상 1번 보기로 나오고 있었습니다. 전 문항의 보기 순서를 다시 섞어 정답 위치가 2~4번에 고르게 분산되도록 수정했습니다. (`Code.gs`의 `ANSWER_KEY`는 옵션 `id` 기준으로 채점하므로 순서 변경은 채점 로직에 영향 없음)

## 스테이지별 진도 공개(잠금) 기능

수업 진도에 맞춰 교사가 스테이지를 하나씩 열어줄 수 있도록 잠금 기능을 추가했습니다.

- **기본값**: 1단계는 항상 공개, 나머지 스테이지는 전부 비공개(잠김)로 시작합니다.
- **교사 조작**: `hub.html`의 관리자 화면(PIN 로그인 필요)에서 스테이지별 토글로 열고 잠글 수 있습니다. 1단계는 토글이 비활성화되어 있어 잠글 수 없습니다.
- **학생 쪽 차단**: 잠긴 스테이지는 `stage.html?id=...` URL을 직접 입력해도 학생 식별 화면조차 뜨지 않고 "아직 열리지 않았습니다" 안내만 표시됩니다. 서버(`Code.gs`)의 `handleSubmit`에서도 잠긴 스테이지의 제출 자체를 거부하므로, 브라우저 콘솔로 우회 제출을 시도해도 채점되지 않습니다.
- **다음 관문 안내**: 한 스테이지를 다 풀면 다음 스테이지가 열려 있을 때만 이동 링크가 보이고, 잠겨 있으면 "아직 열리지 않았습니다" 안내로 대체됩니다.
- 서버 쪽 구현은 `설정` 시트에 `stageOpen_<stageId>` 키로 저장되며, `getSettings` 응답에 `stageOpen` 맵으로 함께 내려갑니다.

## 다음 단계

같은 패턴(`data/stages/*.json` 추가 + `assets/js/config.js`의 `STAGE_LIST`에 등록 + `appsscript/Code.gs`의 `ANSWER_KEY`에 정답 추가)으로 17단계(데이터 분석, "예언자의 탑")부터 이어서 제작합니다. 커리큘럼 전체 순서는 매핑 문서의 2절 표를 따릅니다. 새 문항을 만들 때는 정답 위치를 처음부터 1번(첫 보기)이 아닌 곳에 배치하도록 유의합니다.
